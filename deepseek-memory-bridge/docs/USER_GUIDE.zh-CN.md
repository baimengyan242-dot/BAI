# DeepSeek 记忆桥完整使用说明

适用版本：插件 0.2.2；已验证宿主：DeepSeek Harness（DSH）0.2.2-rc.1、Cordis 4.1.0。插件在 DSH 中使用中文界面。DSH 仍处于预览阶段，升级宿主后需要重新验证兼容性。

[English guide](USER_GUIDE.md) · [项目首页](../README.md) · [版本记录](../CHANGELOG.md) · [测试与限制](test-report.md)

## 1. 插件能做什么

插件保存你手动导出的 DeepSeek 历史文件，提供原文检索、候选记忆提取、来源审核、冲突处理、跨会话召回、备份恢复和存储迁移。

三个概念需要区分：

| 名称 | 含义 |
| --- | --- |
| 原始历史 | 导入文件、会话、消息及其未知字段。确认导入后可在“历史记录”读取。 |
| 候选记忆 | 从用户陈述中提取的长期信息。候选需要人工审核。 |
| 已确认记忆 | 经过审核的记忆。开启自动召回后，相关、未过期、无未解决冲突的条目才可能进入新会话上下文。 |

导入历史不等于所有内容都变成长期记忆。候选数量为零时，已导入的原文仍可检索。插件无法恢复 DeepSeek 服务端未导出的内部记忆，也不会自动登录网页、读取 Cookie 或复用 DSH 凭据。

## 2. 安装与升级

### 安装准备

从仓库 `release` 目录下载 `dsh-deepseek-memory-bridge-0.2.2.tgz`。可用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 对照同目录的 `checksums.json` 核对文件。

完全退出 DSH。关闭窗口可能只是最小化到托盘，请在系统托盘中右键 DSH，选择“退出”。安装和离线 CLI 操作前都应确认后台进程已退出。

### 使用桌面自带命令安装

在 PowerShell 中执行以下示例，将两个路径替换为你自己的实际位置：

```powershell
$DshCommand = 'D:\Apps\DeepSeekHarness\resources\runtime\cli\bin\dsh.cmd'
$Package = 'D:\Downloads\dsh-deepseek-memory-bridge-0.2.2.tgz'
& $DshCommand plugin --profile desktop add ('file:' + $Package)
```

管理 `desktop` 配置时，应使用桌面安装目录内的命令。另行安装的全局 `dsh` 命令可能无法管理桌面专用配置。首次安装依赖可能需要连接 npm registry；日常本地提取和检索不依赖在线模型。

也可以使用源码附带的安装脚本：

```powershell
& 'D:\Projects\deepseek-memory-bridge\scripts\install.ps1' `
  -DshCommand $DshCommand -Profile desktop -Package $Package
```

升级到新的 `.tgz` 文件也使用同一条 `plugin ... add` 命令。升级保留已有数据和所选存储位置；从 0.2.0 或 0.2.1 升级到 0.2.2 后不需要重新导入或重新迁移。

重新打开 DSH，进入“设置 → DeepSeek 记忆桥”。界面右上角的“使用说明”可打开本手册。离线时，可在已安装插件的 `docs` 目录或源码包中阅读本文件。

### Web 配置

Web 宿主需使用同版本官方 CLI。以下示例选择标准 `web` 配置；自定义配置使用自己的名称：

```powershell
dsh plugin --profile web add 'file:D:\Downloads\dsh-deepseek-memory-bridge-0.2.2.tgz'
dsh --profile web --no-open
```

连接远程 DSH 时，导入文件、存储盘符和文件夹都属于 DSH 宿主所在电脑。浏览器所在电脑的 D 盘不一定是宿主的 D 盘。

## 3. 界面入口

| 页面 | 主要用途 |
| --- | --- |
| 导入中心 | 选择 ZIP/JSON、查看预览、确认或继续导入。 |
| 记忆管理 | 按状态和分类筛选，审核、编辑、合并、删除，查看来源和修订。 |
| 历史记录 | 按消息关键词查找原始会话，分页读取及切换历史版本。 |

## 4. 导入 DeepSeek 历史

1. 在 DeepSeek 网页端手动导出历史数据，保留下载到的原文件。
2. 打开“导入中心”，选择 `.zip` 或 `.json`。
3. 等待上传、解析和重复检查。此时只生成预览，还没有提交到活动历史库。
4. 查看可解析会话、消息、重复会话、新版本、异常和警告。展开“格式说明与异常报告”了解识别范围。
5. 点击“核对并导入”，核对确认窗口中的文件和范围，勾选确认后执行。
6. 导入完成后，到“历史记录”读取原文，到“记忆管理”审核候选。

默认归档上限为 512 MiB，解压总量上限为 1 GiB，另有文件数量、单项大小、压缩比例、JSON 深度及单会话内存限制。加密 ZIP、符号链接、不安全路径、重复或大小写冲突文件名、CRC 错误和不完整 JSON 会被拒绝。

支持的结构包括会话数组、嵌套会话容器和 mapping 树。树形会话保留全部分支，列表顺序采用导出节点顺序，分支关系保存在原始字段中。未知格式需要增加适配器；提供问题样本前应脱敏。模拟测试不能保证兼容所有官方导出变体。

### 重复、增量与中断

- 相同原文件按哈希去重，不重复提交相同消息。
- 已有会话的新内容保存为新版本，旧版本仍可读取；重导入已知旧版本不会使当前版本倒退。
- 导入按批次提交并保存进度。中断后可在原任务中“继续导入”。
- 预览解析失败不会将部分预览提交到活动库。修改过的文件需要重新预览。

## 5. 阅读原始内容

进入“历史记录”，输入原始消息中的关键词，点击“查看原文”。详情支持每页 50 条消息、上一页/下一页、版本选择、消息 ID 和原始字段查看，以及下载会话原始字段。

原始导出文件按字节保存；会话未知字段、附件元数据等也保留在原始记录中。ZIP 内非 JSON 附件会保留，但不会自动执行其中的 HTML、脚本或程序。

下载的会话 JSON 是规范化后保存的原始字段。涉及 JSON 数字精确字面形式等问题时，最初归档的导出文件仍是最终依据。

## 6. 审核和管理记忆

### 审核原则

本地规则只识别一部分明确的长期用户陈述，排除常见凭据、可疑指令和假设表达，默认不把 AI 回复当作用户事实。审核时应查看来源引文、原始时间、会话和具体版本，而不是仅看候选句子。

“查看证据 / 编辑”可以查看来源、修改内容、分类和作用域。确认后才允许自动召回；拒绝候选不会删除原始聊天。分类包括个人背景、用户偏好、学习研究、技术环境、项目、知识和待验证信息。

### 作用域与到期

`global` 表示全局。项目作用域按工作目录字符串匹配；不同目录字符串可能对应不同作用域。不要把只对某个项目成立的信息误设为全局。到期记忆不会被自动召回。

### 编辑、合并、修订

编辑后的条目重新进入候选审核。勾选两条以上相关记忆可合并，合并后保留来源，原条目标为已更新，新条目仍需审核。修订历史支持回滚；回滚结果同样重新审核。

### 删除和永久移除

“删除”会停止召回并保留修订，便于回滚。“永久移除记忆”删除活动数据库中的该条记忆及修订，并在操作前创建备份。

两种操作都不会自动删除原始聊天、既有备份、导出文件或系统备份，也不能保证物理介质擦除。

## 7. 处理冲突

对同一作用域中同一已识别属性的不同值，插件保留旧值和新值，要求在“冲突审核”中选择。不要仅按日期决定，先比较来源和适用条件。

未解决的冲突不能直接确认；涉及冲突的条目也不会作为确定事实自动召回。解决后，保留项可成为已确认条目，另一项标为已更新。回滚旧修订可能重新激活矛盾，需要再次处理。

自动冲突检测只覆盖有限的已识别属性，不能发现所有语义矛盾。

## 8. 自动召回与新会话

进入“设置与备份”，勾选“自动召回已确认、相关且未过期的用户陈述”，设置条数和 Token 上限，点击“保存设置”并确认。

默认关闭自动召回，默认最多 6 条、保守 Token 上限 800。预算采用保守估算，不是模型的精确分词结果。插件根据用户当前输入检索相关的已确认信息，并附带记忆 ID、来源会话、消息和版本。

候选、被拒绝、已删除、到期或存在未解决冲突的条目不会正常进入自动召回。原始历史中的指令不会因此被执行。

检索使用 SQLite FTS5、词语和 CJK 双字组合，没有向量 Embedding，同义改写可能漏检。可改用原文关键词，或到“历史记录”查找。启用其他记忆插件时，应检查重复注入。

## 9. 可选模型提取

在原始会话详情中展开“可选模型提取”。这一步与自动召回不同，是从某个已有会话进一步提取候选。

| 字段 | 填写方式 |
| --- | --- |
| 兼容 API 基地址 | 使用 OpenAI 兼容服务的基地址，例如本机 `http://127.0.0.1:11434/v1/`。 |
| 模型名称 | 填服务端实际可用的模型名称。 |
| API Key 环境变量名称 | 填变量名，例如 `MEMORY_EXTRACT_API_KEY`，不填密钥本身；该变量需对 DSH 宿主进程可见。 |
| 远程发送授权 | 若地址为远程服务，需为本次操作单独勾选并确认。 |

远程服务必须使用 HTTPS；本机回环地址可使用 HTTP。插件只发送不含常见凭据的用户消息，不把 AI 回复作为用户事实。来源引文必须能匹配对应用户消息，模型结果仍需审核。

远程服务可能自行计费，费用由所选服务决定。未授权时插件不会进行本次远程发送，也不会自动使用 DSH 的模型凭据。

## 10. 迁移到 D 盘或其他盘

如果已经迁移到正确位置，只需检查“当前记忆库”，无需再次迁移。

1. 打开“设置与备份 → 存储位置”。
2. 点击“选择文件夹”使用宿主文件夹选择器，或点击“浏览磁盘”逐层选择已有目录。
3. 新目录可直接在“目标文件夹”中输入，例如 `D:\DeepSeekMemoryBridge`。不要只填 `D:\`。
4. 确认目标为空，且与源目录相互独立；两者不能相同，也不能相互包含。
5. 点击“迁移当前记忆库”，核对源目录、目标目录和操作范围，再勾选确认。
6. 等待数据库和文件复制、哈希校验及切换完成。查看“当前记忆库”，重启后再次核对。

迁移包括数据库、原始存档、备份、导出、恢复安全副本、未完成的导入和上传等本插件目录内容。校验成功并切换到新库后才删除旧目录。复制或校验失败时保留原库；若其他程序阻止删除旧文件，界面会提示旧文件仍在，需核实新库后再处理占用。

源路径和目标路径不能经过符号链接或目录联接。请预留足够磁盘空间，因为迁移先创建完整副本。

新 Windows 库在 D 盘可用时默认使用 `D:\DeepSeekMemoryBridge`。已有旧库会继续可读，需显式迁移。位置由 `$DSH_HOME/memory-bridge-location.json` 记住；默认 DSH_HOME 通常为用户目录中的 `.dsh`。该小配置保存路径和时间，不保存聊天正文。

迁移不会搬动 DSH 安装目录、宿主自身的会话配置或其他插件的数据。所选盘暂时不可用时，插件会报错，不会在 C 盘悄悄创建空库替代。

## 11. 打开其他盘上已有的数据

在“目标文件夹”中选择已有 Memory Bridge 库的完整目录，点击“打开已有记忆库”并确认。目录内应包含 `memory.sqlite` 和对应原始存档；复制库时应在关闭写入进程后复制整个目录，不要只复制数据库文件。

此操作切换活动库、保留当前旧目录，不会将两个库合并。所选库中遗留的待确认操作会取消，以免执行旧申请。切换后可在“历史记录”和“记忆管理”读取该库内容。

如果手头只有 DeepSeek 导出的 ZIP/JSON，应使用“导入中心”；它不是可直接打开的记忆库目录。

## 12. 备份、恢复与导出

### 完整备份

导入前后会自动备份，也可点击“创建备份”并确认。完整快照包含一致性的 SQLite 数据库、原始存档和暂存内容，并带文件哈希清单。

“自动保留备份数”默认 10。创建备份时会按保留数量清理较旧快照，需要长期保留的备份应另行复制到安全位置。

### 恢复

在备份列表选择“恢复”，核对确认。恢复会替换活动库和原始存档，先保存当前状态，再检查备份的路径、哈希、数据库结构和完整性。恢复安全副本与普通备份的保留方式不同，不应假定其会随普通快照自动轮换。

迁移存储位置后，旧备份仍可恢复，活动存档路径会重写为当前目录。恢复后旧的待确认操作会取消。

### JSON / Markdown 导出

点击“导出 JSON”或“导出 Markdown”并确认。完成提示会显示文件的完整位置。界面导出的是记忆列表；它不能代替完整备份恢复数据库和原始历史。CLI 的导出申请可通过 `includeRaw:true` 另附原始存档。

数据库、原文、备份和导出均未加密。不要把私人库、导出或备份上传到公开仓库。

## 13. 确认机制

导入、审核、编辑、删除、合并、冲突处理、回滚、备份、恢复、导出、设置和存储切换等写操作需要确认。

申请会出现在“待确认操作”。点击“核对操作”查看完整参数，勾选确认后执行；不需要的申请可取消。确认码有效期为 24 小时，过期后需重新申请。AI 工具只能提出修改申请，不能自行取得确认码完成修改。

确认窗口中的 ID、路径、类别键和 API 字段是技术标识，保持其原值，不要手动翻译。

## 14. CLI 与故障时管理

使用 CLI 管理桌面正在使用的库前，先彻底退出 DSH。一个库只允许一个写入进程。源码环境需 Node.js 24.9 或更高版本及项目依赖；普通桌面用户可优先使用原生界面。

在项目目录执行：

```powershell
node dist/cli.js help
node dist/cli.js stats
node dist/cli.js history '关键词'
node dist/cli.js search '关键词'
node dist/cli.js memories candidate
node dist/cli.js read CONVERSATION_ID
node dist/cli.js backups
```

默认使用已保存的位置。`--data-dir PATH` 显式指定库，`--location-file PATH` 指定独立位置配置。迁移后不要沿用指向已删除 C 盘旧目录的显式参数。

写入分为提出申请、查看参数、确认三步，例如：

```powershell
node dist/cli.js import 'D:\Exports\deepseek.zip'
node dist/cli.js propose import --json '{"id":"PREVIEW_ID"}'
node dist/cli.js actions
node dist/cli.js confirm ACTION_ID --nonce CONFIRMATION_CODE
```

`PREVIEW_ID`、`ACTION_ID` 和 `CONFIRMATION_CODE` 需替换为实际输出，不应直接照抄。CLI `actions` 会显示确认码，请勿公开终端截图。

常用申请参数如下，执行前均需检查 `actions`：

| 类型 | JSON 参数要点 |
| --- | --- |
| `import` | `id`：预览任务 ID。 |
| `review` | `id`、`status`（`confirmed` 或 `rejected`），可带 `revision`。 |
| `update` | `id`、`content`、可选 `category`/`scope`/`revision`。 |
| `delete` / `purge` | `id`；前者软删除，后者永久移除活动记忆及修订。 |
| `merge` | `ids` 数组、`content`。 |
| `resolve` | `id`：冲突 ID；`keep`：`old` 或 `new`。 |
| `rollback` | `id`、`targetRevision`，可带当前 `revision`。 |
| `backup` | 空对象 `{}`。 |
| `restore` | `backupId`。 |
| `export` | `format`：`json` 或 `markdown`；可带 `includeRaw`。 |
| `settings` | `autoRecall`、`recallBudgetTokens`、`recallLimit`、`backupKeep`。 |
| `storage` | `path`：完整目标路径；`mode`：`migrate` 或 `open`。 |
| `model-extract` | `id`：会话 ID；`endpoint`、`model`、可选 `keyEnv`，远程时需 `authorizeRemote:true`。 |

例如迁移申请中的反斜杠需要符合 JSON 转义规则：

```powershell
node dist/cli.js propose storage --json '{"path":"D:\\DeepSeekMemoryBridge","mode":"migrate"}'
```

## 15. 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 设置页没有插件 | 检查正确 profile、插件是否选中、DSH 版本，安装后重启。桌面配置使用桌面自带 CLI。 |
| 仍显示英文 | 确认已安装 0.2.2，彻底退出并重启。仓库的英文文档入口不代表 DSH 界面语言。 |
| 仍显示旧存储位置 | 检查“当前记忆库”和位置配置。已有库不会自动搬迁，需要明确选择“迁移当前记忆库”。 |
| 目标目录不为空 | 改选空目录；若那里已有完整记忆库，选择“打开已有记忆库”。 |
| 已保存的库不可用 | 重新连接磁盘；手工移动过目录时，关闭 DSH、备份并修正位置配置。 |
| 提示另一个进程正在使用 | 完全退出 DSH 或其他 CLI。不要删除仍属于运行进程的锁文件。 |
| 导入成功但没有候选 | 到“历史记录”检查原文。本地规则识别范围有限，可在会话详情使用可选模型提取。 |
| 搜索不到某条内容 | 尝试原文关键词，检查当前库、状态、项目作用域、到期和冲突。 |
| 无法确认候选 | 检查是否有未处理冲突、是否缺少用户直接证据、修订是否已变化。 |
| 远程模型提取失败 | 检查 HTTPS 基地址、实际模型名、宿主环境变量和本次远程授权。 |
| 记忆已删但原文还在 | 删除记忆不等于删除原始历史，旧备份和导出也可能仍有该内容。 |

排查时优先保留原始导出和完整库副本，不要反复删除目录尝试修复。详细技术限制见 [测试报告](test-report.md) 和 [故障说明](troubleshooting.md)。

## 16. 卸载与数据保留

完全退出 DSH 后执行：

```powershell
& $DshCommand plugin --profile desktop remove dsh-deepseek-memory-bridge
```

卸载保留数据库、原始存档、备份、导出及已选位置记录。重新安装后可继续使用原库。要彻底删除私人数据，需要先确认不再需要历史、备份、导出及恢复安全副本，再自行处理对应文件；卸载本身不承担物理介质擦除。
